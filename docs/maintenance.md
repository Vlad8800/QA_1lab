## Правило злиття

**Зміна коду = зміна зачепленої документації.** Перед merge до main maintainer перевіряє impact: HTTP/компоненти → SDD; запуск/config/CI → ISD; поведінка/онбординг → README; нове рішення → новий ADR. Не зливати PR без відповідного оновлення; для зміни без документаційного впливу потрібне явне обґрунтування reviewer. Це процесний регламент: required check і branch protection на GitHub цим файлом не встановлюються.

Рев’ю проводиться також одразу після зміни, не чекаючи 90/180 днів. Reviewer перевіряє команди на чистій копії, посилання, контракти й матрицю аудиторій, оновлює last_review/review_date. Для ADR не переписувати контекст/рішення; новий підхід отримує новий номер, старому додається superseded-зв’язок. Відповідальний за незалежне рев’ю наразі не призначений — це ризик передачі знань.
