# RFC-001 — контрольована деградація export при недоступному сховищі

Ініціатор: Vlad8800. Дата: 2026-11-20 UTC. Вимога REQ-OPS-001:
недоступність repository має повертати 503 з Retry-After без витоку даних;
після відновлення залежності export знову повертає 200.

Мета: замінити неконтрольовану 500 на явну тимчасову недоступність та додати регресію.
ITIL: **нормальна** зміна, бо це нова обробка помилки, яка потребує оцінювання.
Ризик: ймовірність 2/5 × наслідки 3/5 = **6/25**, середній (1–4 низький, 5–9 середній, 10–25 високий).
Це пріоритетний бал, не грошова очікувана втрата.
Вікно: модельне staging-вікно 2026-11-21 09:00–09:30 UTC, після погодження.
Локальні тести можуть передувати цьому вікну; продуктивний rollout не заявляється.

Ланцюг станів: Draft → Assessment → Pending CCB → Approved / Rejected → Implemented → Closed.
Rejected — кінцевий стан до перегляду заявки; до Implemented переходить лише Approved.
Умовне CCB дозволяє локальний експеримент. Production — Pending acceptance.
Реєстрація у зовнішньому трекері та фактичний стан: див. Lab12/evidence/tracker.json.

конкретного change-коміту на окремій гілці; повторити export/security регресію.
