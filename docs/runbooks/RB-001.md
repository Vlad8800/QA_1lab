# RB-001 — відновлення експорту персональних даних

## Ідентифікатор і відповідальність

RB-001, власник SRE (у навчальному середовищі — Vlad8800). Обсяг: один процес FastAPI.
Рівень автоматизації **1 — скриптований**: команди та drill повторювані, але рішення про
відновлення, права доступу й приймання результату залишаються за оператором.
Self-healing без постійного сховища може втратити зміни, тому рівень 3 не заявляється.

## Тригер

Алерти EXPORT_FAILURE, API_UNAVAILABLE або RESTORE_DRILL_FAILED з [каталогу](../operations/alerts.md).
Плановий щотижневий drill — окремий maintenance event, а не аварійний алерт.

## Передумови

L2/SRE має право запускати сервіс і читати зашифровані копії, Python 3.12 та встановлені залежності.
Команди PowerShell виконувати з кореня QA_1lab. Порт 8012 виділений для перевірки.
Експорт містить персональні дані: не вставляти тіло відповіді в чат/публічний лог.

## Покрокові дії

1. Зареєструвати інцидент, записати час UTC:

```powershell
[DateTime]::UtcNow.ToString('o')
git rev-parse HEAD
```

1. Перевірити policy та процес. Не завершувати всі Python-процеси:

```powershell
Test-Path runtime/shipping-policy.json
Get-NetTCPConnection -LocalPort 8012 -State Listen -ErrorAction SilentlyContinue
```

1. За відсутності конфігурації відновити затверджений конфіг, не створювати вигадану політику:

```powershell
New-Item -ItemType Directory runtime -Force
Copy-Item config/shipping-policy.example.json runtime/shipping-policy.json
```

1. Для продуктивного адаптера спочатку відновити БД/сховище та перевірити доступ,
потім запускати API. У поточному demo БД немає: repository створюється у пам'яті,
і перезапуск НЕ відновлює попередні записи. Див. [backup policy](../operations/backup-policy.md).

2. У виділеному терміналі запустити перевірюваний екземпляр:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8012
```

1. В іншому терміналі перевірити операції:

```powershell
Invoke-RestMethod http://127.0.0.1:8012/api/v1/shipping/policy
$result = Invoke-WebRequest http://127.0.0.1:8012/api/v1/users/usr_101/personal-data -Headers @{'X-Actor-ID'='usr_101'}
$result.StatusCode
python -m pytest tests/test_personal_data_export.py tests/test_lab12_storage_failure.py -q
```

## Верифікація

Policy та авторизований export повертають 200; чужий export — 403; відсутня авторизація — 401.
При недоступності repository очікується 503 з Retry-After, без приватних даних у помилці.
503 — контрольована деградація, вона все одно витрачає availability budget.
Відновлення вважається завершеним лише після 3 успішних проб і 5 хвилин спостереження.
Окремий швидкий навчальний тест не замінює це вікно спостереження.

## Відкат

Зупинити лише власний процес Ctrl+C, повернути попередній артефакт у новий каталог,
повернути його конфіг та перевірену копію даних, запустити тими самими командами.
Не застосовувати git reset --hard до робочої папки. Для цієї навчальної зміни
можна виконати git revert конкретного коміту виправлення на окремій гілці.
Якщо повертається помилка 500 — лишити експорт недоступним, не видавати неповний файл як успішний.

## Ескалація

L1 підтверджує SEV-2 за 15 хв; за відсутності відновлення за 10 хв передає L2/SRE.
За 30 хв залучити L3/архітектора. Витік персональних даних — негайно SEV-1 та DPO.
Канали й адресати визначені у [плані супроводу](../maintenance-plan.md).
