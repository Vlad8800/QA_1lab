# SWEBOK Maintenance Plan — QA_1lab

## Обсяг, відповідальність та види супроводу

Власник Vlad8800; один студент виконує навчальні ролі, реальне чергування 24/7 не заявляється.
Corrective — виправлення інцидентів; adaptive — заміна persistence/auth адаптерів;
perfective — швидкість і зручність документації; preventive — fault-injection регресії.

## L1 / L2 / L3

| Лінія | Дії | Коли передати |
| --- | --- | --- |
| L1 оператор | Прийняти звернення, визначити SEV, зібрати ID/час без PII, виконати probe | Немає відновлення за 10 хв або потрібен доступ до сховища -> L2 |
| L2 SRE | RB-001, залежності, restore drill, перевірка даних, rollback | За 30 хв немає рішення або потрібна зміна коду -> L3 |
| L3 розробник/архітектор | Виправлення, регресія, ADR/RFC, аналіз системних причин | Витік даних -> власник продукту та DPO негайно |

## Known Issues та обходи

| Проблема | Обхід та обмеження |
| --- | --- |
| RAM persistence | Не перезапускати для «відновлення даних»; зберігати узгоджені копії, планувати persistent adapter |
| Недоступність repository | 503/Retry-After; відновити залежність, перевірити 200, не видавати порожній export |
| Demo actor headers | Використовувати лише в ізольованому demo; до production потрібний перевірений identity provider |
| Немає підключеного alert backend | Ручні probes для локального demo; production no-go до перевірки доставки алертів |
